Leave a row blank if it doesn't exist for this stack. Blank means "skip it",
not "guess at it".

- **db migrate** is blank on purpose: Mongoose has no migration step. The schema
  lives in the model definitions and MongoDB creates collections on first write.
- **db seed** runs `scripts/seed.ts`. It is safe to run repeatedly: leads are
  matched on `name` and updated in place, so a re-run resets the demo data
  rather than duplicating it.
- **deploy** is blank because no deploy target has been chosen.

## Conventions

- Source lives in: `src/app/` (App Router — `layout.tsx`, `page.tsx`, `globals.css`)
- Tests live in: next to the code they test, as `*.test.ts` / `*.test.tsx`
  (Vitest's default `include` is `**/*.{test,spec}.?(c|m)[jt]s?(x)`)
- Naming: Next.js file conventions (`page.tsx`, `layout.tsx`, `route.ts`)
- Config: `MONGODB_URI` is read from `.env.local` (gitignored). `.env.example`
  is committed and is the list of variables a new machine has to fill in.
- Mongoose connection: cache the connection promise on `globalThis` so Next's
  hot reload reuses one connection instead of opening a new one on every save.
  **Not written yet** — it lands with the first code that touches the database.
- Anything unusual about this setup:
  - `AGENTS.md` is regenerated by `next dev` and is included by `CLAUDE.md`.
  - `.gitignore` ignores `.env*` but re-includes `!.env.example`.
  - Package manager is npm (`package-lock.json`).
  - Scripts under `scripts/` run through `tsx` with `--conditions=react-server`,
    so they resolve `server-only` modules the way the app does. Plain `node`
    cannot: it will not resolve extensionless TypeScript imports.
  - `npm test` exits 1 while there are no test files (`vitest run` has no
    `--passWithNoTests`). It goes green with the first test.
